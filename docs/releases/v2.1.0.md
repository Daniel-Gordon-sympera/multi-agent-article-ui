# v2.1.0 — Complete local Scout integration

Use this UI with [backend v2.1.0](https://github.com/Daniel-Gordon-sympera/multi-agent-article/releases/tag/v2.1.0).
The repositories share the v2.1.0 release version; the integration contract remains `1`.
Backend repository access is required for its setup guide and validation records.

## What changed

- All screens use complete backend queries, with server filtering and matching signal summaries/exports.
- Signal identity includes the job. Company profiles and copied links load the correct records, including details outside the current page.
- Month-only dates, unknown flags, missing costs, incomplete downloaded-content measurements and live summaries retain their meaning.
- Admins can list API-key metadata; operators can view and reset website access policies with confirmation, CSRF checks and auditing.
- Incompatible backends and unavailable services produce explicit states. Temporary limited fallbacks have been removed.
- The shared `.env.platform`, loopback HTTP setup, generated API types and combined recovery workflow are documented.

## Setup and verification

Follow the shared [GUIDE.md](https://github.com/Daniel-Gordon-sympera/multi-agent-article/blob/v2.1.0/GUIDE.md)
and the local [HOWTO](../../HOWTO.md). Use both v2.1.0 checkouts and keep existing
volumes when upgrading. Database backups include the UI schema; retain artifact
storage separately and reapply bootstrap permissions after restore.

The release passes BFF and frontend tests, type/lint/build checks, mock browser and
accessibility tests, and a separate real API/BFF/browser/database recovery check.
Detailed evidence is maintained in the backend repository.

The supported endpoint is `http://localhost:8080`, bound to loopback. VM deployment
and production HTTPS are outside this release.
